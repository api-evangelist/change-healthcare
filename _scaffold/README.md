# Quarantined scaffold artifacts — NOT published by Change Healthcare

Everything in this folder was **authored by API Evangelist**, not harvested from Change Healthcare.
It is kept for audit history only. Nothing here is wired into `apis.yml`, nothing here is scored,
and nothing here should be treated as a contract this company publishes.

## `graphql/`

- `change-healthcare-schema.graphql` (849 lines)
- `change-healthcare-graphql.md`

Quarantined **2026-08-15**.

These files describe themselves accurately in their own text — the `.graphql` header reads
*"Conceptual schema for the Change Healthcare (Optum/UnitedHealth Group) healthcare transaction and
data platform"*, and the markdown closes with *"This is a conceptual schema derived from Change
Healthcare's public developer documentation, API patterns, and standard healthcare EDI
specifications."* They were generated by API Evangelist on 2026-06-14 as a domain-modelling exercise.

**Change Healthcare has never published a GraphQL API.** Verified 2026-08-15:

| Probe | Result |
|---|---|
| `POST https://apis.changehealthcare.com/graphql` (introspection) | `400 {"error":"invalid_request"}` |
| `POST https://sandbox.apis.changehealthcare.com/graphql` | `400 {"error":"invalid_request"}` |
| `https://api.changehealthcare.com/` | TCP connect timeout on :443 |
| Optum successor portal (`developer.optum.com/eligibilityandclaims`) | REST + X12 EDI only; no GraphQL surface |

The generated file also carried factual errors that had propagated into `apis.yml`: it listed
`https://api.changehealthcare.com` as the base URL (a host that does not accept connections) and
`https://github.com/changehealthcare` as the company GitHub org (it is an empty personal **user**
account, 0 public repos, created 2020-01-03; `GET /orgs/changehealthcare` returns 404).

A conceptual schema on a company profile reads to an agent as a contract the company serves. It is
not one, so the `type: GraphQL` pointer was removed from `apis.yml` in the 2026-08-15 enrichment
pass and the files were moved here rather than deleted, following the `all/meditech/` precedent.
